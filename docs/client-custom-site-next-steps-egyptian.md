أهلاً يا فندم،

بما إنك حطيت الـ API Key في Backend الموقع، فاضل دلوقتي نتأكد إن كود الموقع بيبعت بيانات الطلب إلى Wslahali بعد ما العميل يضغط تأكيد الطلب.

## المطلوب يحصل عند كل Order

لما العميل يعمل طلب من موقعك، الـ Backend عندك لازم يبعت طلب إلى الرابط ده:

```text
POST https://wsalhali.vercel.app/api/integrations/v1/shipments
```

والـ API Key يتبعت في الـ Header بالشكل ده:

```text
Authorization: Bearer API_KEY
```

لا تحط الـ API Key داخل HTML أو JavaScript الظاهر للزوار. خليه داخل Backend أو Environment Variables فقط.

## البيانات المطلوبة في الطلب

لازم الطلب يحتوي على بيانات المرسل والمستلم، مثل:

- اسم المرسل ورقم تليفونه وعنوانه وكود مدينة الإرسال.
- اسم المستلم ورقم تليفونه وعنوانه وكود مدينة الاستلام.
- وزن الشحنة وعدد القطع.
- قيمة COD لو الدفع عند الاستلام.
- رقم الطلب الموجود عندك.

استخدم كود المدينة الذي يتم جلبه من:

```text
GET https://wsalhali.vercel.app/api/integrations/v1/cities
```

## السعر

ما تبعتش `shippingCost` من موقعك. السعر بيتحسب تلقائياً من نظام Wslahali حسب قواعد التسعير والمدينة والوزن والخدمة وCOD، ويرجع لك في نتيجة إنشاء الشحنة.

## منع تكرار الشحنة

مع كل طلب ابعت `Idempotency-Key` مبني على رقم الطلب، مثلاً:

```text
Idempotency-Key: order-10001
```

لو حصل timeout أو اضطر الموقع يعيد نفس الطلب، استخدم نفس المفتاح، عشان ما تتعملش شحنتين لنفس الـ Order.

## نتيجة الطلب الصحيحة

بعد إرسال الطلب، المفروض يرجع:

```text
HTTP 201
```

وفي الرد يظهر رقم تتبع يبدأ بـ `WSL`، مثل:

```json
{
  "data": {
    "trackingNumber": "WSL123456",
    "status": "PENDING",
    "totalCost": 40
  }
}
```

لازم الموقع يحفظ رقم التتبع ده داخل الطلب ويعرضه للعميل.

وفي نفس الوقت، الشحنة المفروض تظهر عندنا في لوحة Wslahali داخل **Admin → Shipments** بحالة `PENDING`.

## اختبار مطلوب دلوقتي

من فضلك اعمل Order تجريبي من الموقع، وبعدها راجع نتيجة استدعاء الـ API من Backend الموقع.

ابعت لنا فقط:

1. هل الطلب رجع `HTTP 201`؟
2. هل ظهر `trackingNumber` يبدأ بـ `WSL`؟
3. رقم التتبع الناتج، لو ظهر.
4. لو حصل خطأ، رقم الحالة مثل `400` أو `401` أو `500` ورسالة الخطأ فقط.

من فضلك لا تبعت الـ API Key أو كلمة المرور أو أي بيانات سرية.

## بالنسبة لتحديث حالة الشحنة

إنشاء الشحنة ورقم التتبع يشتغلان بالـ API فقط. لو عايز حالة الشحنة تتحدث تلقائياً داخل موقعك عند انتقالها إلى `IN_TRANSIT` أو `DELIVERED`، ابعت لنا رابط HTTPS من Backend موقعك لاستقبال Webhook.

مثال:

```text
https://your-domain.com/api/wslahali/webhook
```

الـ Webhook اختياري. من غيره الشحنات هتتعمل عادي، وتقدر تستعلم عن الحالة من خلال:

```text
GET /shipments/{trackingNumber}
```

لكن الحالة لن تتحدث تلقائياً داخل موقعك إلا باستخدام Webhook أو استعلام دوري من الموقع.

بعد نجاح الطلب التجريبي وظهور رقم التتبع، نكون كده تأكدنا إن الربط الأساسي شغال ونقدر نبدأ التشغيل الفعلي.
